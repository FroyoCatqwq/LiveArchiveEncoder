# v8 多语言（i18n）

> 状态：**App 层完整翻译**（2026-10-31）——所有命令的输出、`--help` 的每一行；Core 的句子待下一轮
> 库：[`I18Next.Net`](https://github.com/DarkLiKally/I18Next.Net) 2.0.0（Apache-2.0）

## 1. 为什么用 i18next 而不是手写字典

这个项目的字符串有三个特点，手写字典会在第二个月开始疼：

- **键是嵌套的**（`history.total`），不是平的；
- **句子里有占位符**（"共 {{runs}} 次运行，记录在 {{path}}"），而中英文里数字的位置不一样；
- **英文要复数，中文不要**。今天用 `run(s)` 糊过去，明天就会有人写出 `"{0} run(s)"`，
  后天第三条路径又是另一种写法。

这三个都是 i18next 存在的理由。它还是 JS 版 i18next 的移植，翻译文件格式和 Web 端通用——
如果将来有个网页版界面，资源可以直接共用。

## 2. 分层

| 位置 | 东西 | 为什么在这 |
| --- | --- | --- |
| `Lae.Core/Localization/IMessages.cs` | `IMessages`、`KeyMessages`、`LanguageChoice` | 纯逻辑：接口和"选哪个语言"的规则，零 I/O，可单测 |
| `Lae.Media/Localization/I18NextMessages.cs` | i18next 实现、内嵌资源读取 | 读资源是 I/O，和 `TomlSettingsStore` 同理 |
| `Lae.Media/Localization/locales/{en,zh}/translation.json` | 翻译文件 | 内嵌进程序集 |

**资源内嵌，不放二进制旁边。** v8 是自包含单文件发布，一个散落的 `locales/` 目录会是用户下载包里
第一个丢的东西。csproj 里用 `LogicalName` 把资源名钉死成 `lae.locales.{语言}.{命名空间}.json`，
查找不依赖 MSBuild 的目录转点号规则。

## 3. 语言怎么选

```
LAE_LANG  →  ui.language（settings.toml）  →  en
```

- **规范化**：`zh-CN`、`zh_CN`、`ZH`、`zh-Hans` 都归到 `zh`。
- **不认识的语言落到 en**，不是报错：配置里手写一个 `fr` 不该让程序不会说话。
- **环境变量优先**，这是让 e2e 能测语言切换的唯一干净办法——否则测试要往开发者的
  `%LOCALAPPDATA%` 写设置文件，那正是 v7 e2e 栽过的坑。

```toml
# settings.toml
[ui]
language = "zh"
```

```powershell
$env:LAE_LANG = "zh"; lae history list
```

## 4. 翻译的规矩

1. **一条句子一个键，不拼**。`"{0} runs"` + `"at " + path` 这种写法在中文里语序就错了。
2. **占位符用 `{{name}}`**，值通过匿名对象传：`messages.Get("history.total", new { runs, path })`。
3. **别把变量叫 `count`**。i18next 里 `count` 会触发复数解析，而默认复数解析器读的是
   JSON v1 格式的 `key_plural` 后缀，配错了就是拿到键名。本项目暂时不用复数，
   所以叫 `runs` 而不是 `count`。
4. **缺翻译返回键名，不抛异常**。缺一条翻译是资源文件的缺口，不能让命令失败。

## 5. 进度

**已完整翻译**：所有命令的**输出与描述**——`encode`（计划、结果、进度、错误、提示）、`config`、
`preset`、`setup`、`history`，以及 `--help` 里的每一行（命令一行摘要、参数说明、`-h` 自己那一行）。

**故意不翻的三类**：

| 不翻 | 为什么 |
| --- | --- |
| `config show` 的键名（`defaults.encoder`） | 它是 TOML 里的键，也是 `grep` 要找的字面量 |
| `preset show` / `setup` / `history` 的字段标签 | 同上，它们是配置文件里的名字 |
| FFmpeg 命令行、`note:` 后面的路径与数字 | 命令行的接收者是 FFmpeg，不是人 |

**还没翻：`Lae.Core` 里生成的句子**（约 50 条，`EncodePlan.Problems`、`RecompressPlan`、
`SubtitleChain`、`SubtitleCopy`、`ArgsFragment`、`LegacyV7Converter`）。它们在中文界面里仍以英文出现，
例如计划被拒时那句 `ERROR: ...` 的内容。

原因不是懒：这些是**纯函数产生的句子**，要翻译就得把 `IMessages` 传进 `EncodePlan.Create` 这类函数——
它们在生产代码里有 8 个调用点，**在测试里有 59 个**，而测试断言的是那些英文句子本身。这是一次
把 `IMessages` 变成纯函数参数的机械改造，值得单独一轮做，混在「翻译 App 层」里做会让两边都难以定位。
`EncodeSession` 已经把 `IMessages` 从 `EncodeDependencies` 拿到了，接下来只是往下再传一层。

## 6. 加一条新字符串

1. 在 `locales/en/translation.json` 里按层级加键；
2. 在 `locales/zh/translation.json` 里加同名的中文（**少一条会有测试失败**，见第 7 节）；
3. 代码里 `messages["a.b.c"]` 或 `messages.Format("a.b.c", new { x })`；
4. 命令的构造函数已经能拿到 `IMessages`（`CommandTree` 传的 `host.Messages`），不需要新建。

**键的命名约定**：

| 形状 | 是什么 | 例 |
| --- | --- | --- |
| `X.desc` | 命令的一行摘要 | `encode.desc` |
| `X.opt.NAME` / `X.arg.NAME` | 选项/参数说明（进 `--help`） | `encode.opt.subtitleCopy` |
| `X.error.*` | 以 `ERROR: ` 开头的整句 | `encode.error.noEncoder` |
| `X.<东西>` | 输出里的一行 | `encode.plan.ladderValue` |

**整句进资源文件，包括 `ERROR: ` 前缀**。拼前缀（`"ERROR: " + messages[...]`）在中文里
要变成 `错误：`，那是两处要同时改的东西。

## 7. 测试

| 层 | 测什么 |
| --- | --- |
| Core | `LanguageChoiceTests`：优先级、区域标签、未知语言 |
| Media | `I18NextMessagesTests`：英/中句子、占位符填充、缺键回退键名、未支持语言回退 en、**两个语言的键集必须相同** |
| App | `HistoryTests.TheSameCommandSpeaksTheLanguageItWasGiven`：同一命令两种语言 |
| e2e | `test_language.py`：默认英文、`LAE_LANG=zh`、`ui.language = "zh"`、`zh-CN`、`--help` 被翻译、用量错误被翻译、dry-run 报告被翻译、**两种语言打出的 FFmpeg 命令行逐字节相同** |

「两个语言的键集必须相同」值得单说：回退机制会把「en 有、zh 没有」变成**一句英文夹在中文里**，
不抛异常、不打印键名、看起来不像坏了。这是审查时最容易放过的一类，所以用测试钉住。

最后一条 e2e 是这个功能真正的边界：**翻译只能改措辞，不能改参数**。中文跑出来的命令如果和英文
差一个字节，那就不是翻译，是改了程序行为。

## 8. 已知限制

- **表头与 CJK 对齐**：`history list` 的中文表头按字符数排，不按显示宽度（中文占两格），
  所以和 ASCII 数据列略有错位。`encode` 的报告同样：标签按 11 个字符补空格，中文标签的
  值列会比英文宽两格。要做对得引入东亚宽度计算，暂时不值得。数据列本身不受影响。
- **Core 的句子仍是英文**（见第 5 节），这是下一轮的第一件事。
- **`note:` 前缀仍是英文**：它后面跟着的是 Core 的句子，等那一层翻了一起改。
- **没有 `LAE_LANG=zh` 的补全脚本**：补全候选来自命令树，与语言无关，不需要。

## 9. 换成中文的代价与收益

一句实话：这类工具的用户群大多读得懂 `source / output / quality`，所以翻译的收益不在
"看不懂"，而在**错误与提示**——`ERROR: this FFmpeg build has no encoder named 'flv'` 和
`--size 要的是 宽x高，收到的是 'bad'` 对同一个人的效率不同。所以优先翻的是错误，不是标签。
