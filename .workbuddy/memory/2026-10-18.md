### FFmpeg 工具链（新增 FFmpeg/FfmpegCatalog.cs + FFmpeg/Toolchain.cs）
- 四个来源：btbn(默认,GitHub zip) / gyan(gyan.dev 7z) / avbuild(SourceForge,**手动**) /
  nonfree(GitHub zip)。安装目录 `%LOCALAPPDATA%\LiveArchiveEncoder\ffmpeg\<id>\bin`。
- 四条已实测通过的下载链路：btbn 191MB、gyan 161MB、nonfree 193MB 自动下载 OK；
  avbuild 手工 curl 下载后用 `--ffmpeg-archive` 装 OK。
- **下载踩坑（别再查第二遍）**：
  1. SourceForge 的 `/files/.../download` 会返回 **HTML 跳转页**（131KB），下载器会
     当成压缩包存下来 → 加了 magic bytes 校验（PK / 37 7A BC AF 27 1C）。
  2. SourceForge 对 aria2c 默认 UA 和"完整 Chrome UA"都 403，只对短 UA
     `Mozilla/5.0 (Windows NT 10.0; Win64; x64)` 放行；连接数 16 也 403、4 才行。
     最后干脆让 avbuild 走手动下载。
  3. Windows 自带 `tar.exe` **不能**解 7z（"This does not look like a tar archive"），
     必须用 `7z` / `7za` / `7zz`（本机 Scoop 有 7z）。
- 设计红线：**受管理构建只有在被显式选定（`--ffmpeg-source <id>` 或配置里存了）时才
  生效**；没动过的配置一律用系统 FFmpeg。否则随手装一个构建会悄悄换掉所有脚本化
  运行的产物。加 `"path"` 作为回到系统 FFmpeg 的显式值。

### compare_matrix 的 mpeg1video_mpg 假失败（已根治，别再当成随机抖动）
- 现象：aot 全矩阵跑出 `mpeg1video_mpg FAIL`，单独重跑却又 PASS。
- 取证：`-count_frames` 数出来**两边帧数都是 120**，但容器时长在 4.901 / 4.942 /
  4.984 之间跳。**Python 基线自己两次跑就得到 4.942 和 4.984** → 不是端口 bug。
- 根因：MPEG-PS/TS 的时间戳来自管道字节的实际到达时刻（写入节奏），不是帧计数；
  机器负载一变，同一串帧的容器时长就差约一帧。
- 修法：`PACING_DURATION_FORMATS = {mpeg, mpegts, mpegvideo}` 的 duration 用
  **0.12s 容差**判定，同时把精确字段 `frames`（nb_read_frames）纳入 STRUCTURAL ——
  精确性由帧数承担，其余字段仍要求完全一致。另加 `CM_ONLY=case1,case2` 只跑指定用例。
- 结论：三套产物现在都是 12/12、11/11、35/35、25/25、30/30 全绿。
